## Summary
Implement a new responsive `FullLeaderboard` page for the Peptrace web app, displaying a product-specific leaderboard (starting with Retatrutide) and its lab test history. This feature introduces a new frontend page component with five internal sections, registers a dynamic route in `App.tsx`, and consumes existing shared layout components (`HeaderBar`, `HomeTopInfo`, `SiteFooter`). The backend requires two new read-only API endpoints to serve product-scoped leaderboard and test history data. No shared service integrations change.

**Layer verdicts**
- **frontend**: Changes required — new route, page component, responsive CSS, and shared component consumption.
- **api**: Changes required — new endpoints to supply product-specific vendor rankings and test history.
- **database**: None required — the existing entities (Product, Vendor, Test, Leaderboard entry) are assumed to support the fields surfaced in the design. If gaps exist (e.g., `customerRating`, `purityRating`, `nCount`, `coaUrl`), a follow-up migration will be needed.
- **ios**: None required — the app is a Capacitor hybrid; the new web page is automatically available in the iOS shell with no native changes.
- **android**: None required — the app is a Capacitor hybrid; the new web page is automatically available in the Android shell with no native changes.

- **Query for codebase inspection** before building tables: check `VendorsList.tsx` and `VendorDetails.tsx` for existing table markup, shared table utilities, or design-system table primitives that can be reused inside `VendorsPanel` and `TestHistorySection`.

## API Changes
- **Create** `GET /products/:slug/leaderboard`
  - Purpose: Return product metadata and ranked vendor list for the page header and vendors panel.
  - Request: path parameter `slug`; optional query parameters for client-side filtering (`search`, `ratingSort`, `rating`, `price`, `stars`, `n`).
  - Response: product metadata (`name`, `slug`, `vendorCount`, `testCount`, `firstTestDate`, `latestTestDate`), methodology metadata (`type`, `purityThreshold`, `doseTolerance`), and an array of vendor leaderboard entries (`rank`, `name`, `slug`, `initials`, `isVerified`, `pricePerMg`, `customerRating`, `purityRating`, `nCount`).
- **Create** `GET /products/:slug/tests`
  - Purpose: Return lab test history for the test history table.
  - Request: path parameter `slug`.
  - Response: stats block (`total`, `pass`, `fail`) and an array of test rows (`date`, `result`, `productName`, `vendorName`, `labName`, `purity`, `identityPass`, `dosageDeviation`, `testedMg`, `labelMg`, `batch`, `sender`, `coaUrl`).
- **Rationale**: The existing API surface (`/products`, `/leaderboards`, `/vendors`) does not expose a dedicated, product-scoped leaderboard combined with test history. These endpoints provide the precise data shapes the new UI requires.
