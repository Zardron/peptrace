## Summary
Implement the new **Vendor Details** screen at `/vendors/:id` per the Figma baseline (canonical frame `398:1680`, responsive variants `450:1815` and `523:2085`). This is a new route and page component; the codebase currently only has the `/vendors` list view. The plan covers the responsive frontend page, a new backend endpoint to serve deep vendor data, and data model extensions to support profile fields and rich test history. **iOS and Android**: None required — no Capacitor native shell changes are needed; the new route renders inside the existing WebView.

## Frontend Changes
- **Routing (`frontend/src/App.tsx`)**: Add an `isVendorDetailsPage` guard and `/vendors/:id` route branch before the existing `/vendors` list branch. Render the new `VendorDetails` component inside the standard `<main>` + `SiteFooter` layout, passing the URL slug as a prop.
- **VendorDetails component (`frontend/src/components/VendorDetails/`)**: Create `VendorDetails.tsx` and `VendorDetails.css`. Build the page as a single responsive component with the following internal sections:
  - `VendorDetailContent` (back link, vendor name)
  - `VendorMainRow` (`VendorProfile` with avatar/meta; `ActionCards` for Website, Intelligence Report, Monitor)
  - `TestSupplyButton` CTA
  - `OverviewSection` with tab bar (Overview, Retatrutide, GHK-Cu), rating column (score, rank, progress bar, methodology), analysis column, and filter row
  - `IntelligenceReportCard`
  - `BelowReportSection` using a two-column layout: left column contains `PeptidesContainer` (pricing/rating table) and `ContactContainer` (channels list); right column contains `RatingTrendContainer` (inline SVG chart) and `MembershipCard`
  - `TestHistorySection` with paginated table and `Pagination` controls
  - `AboutSection` and `CorrectionsSection`
  - Final `TestMySupplyButton` CTA
- **Assets**: Add SVG icons to `frontend/src/assets/vendor-details/` (or reuse existing assets) for arrows, globe, external-link, file-text, chevron, bell, message-circle, mail, credit-card, and check-circle.
- **Component index (`frontend/src/components/index.ts`)**: Export `VendorDetails`.
- **List navigation (`frontend/src/components/VendorsList/VendorsList.tsx`)**: Convert table rows into anchors linking to `/vendors/${row.id}` so the existing App.tsx click interceptor handles routing.
- **Responsive behavior**: One `VendorDetails` component with scoped CSS breakpoints:
  - Mobile (0–568px): single column, full-width cards, horizontally scrollable tables, simplified chart
  - Tablet (569–1091px): two-column main content, scaled chart, compact spacing
  - Desktop (≥1092px): full two-column layout, side-by-side action cards, full chart
- **Reused components**: `HeaderBar` (with `activeRoute="/vendors"`), `SiteFooter`, and existing `AuthModal` behavior.

## API Changes
- **Create `GET /vendors/:id`**: Add a new public endpoint that returns a comprehensive vendor detail payload. The handler must aggregate:
  - Derived stats from existing relationships (test count, peptide count, rank, pass/fail totals)
  - Static profile fields from the Vendor record (location, website, avatar, about, contacts, intelligence report metadata)
  - Peptide pricing/rating rows per vendor
  - Rating trend time-series data for chart rendering
  - Paginated test history items with purity, dosage, label, batch, sender, lab, and COA URL
- **Request shape**: path parameter `id` (vendor id or slug).
- **Response shape**: see the JSON plan for the full `vendor` DTO, including nested `peptides`, `ratingTrend`, and paginated `testHistory`.

## Data Model Changes
- **Extend `Vendor` table**: Add `slug`, `location`, `websiteUrl`, `avatarUrl`, `about` (text), `contactChannels` (JSONB array), and `intelligenceReport` (JSONB metadata). These fields power the profile header, contact section, about/corrections, and intelligence report card.
- **Extend `Test` table**: Add explicit `result` (pass/fail), `purity` (numeric), `dosageDeviation`, `testedMg`, `labelMg`, `batchInfo`, `sender`, `coaUrl`, and `labName`. These fields are required to render the test history table and vendor aggregates accurately.
- **Storage**: app DB (existing `vendors` and `tests` tables). No new tables required unless the project prefers normalizing contacts or corrections into separate relations.

## Shared Services
- **shared-services/admin-portal**: No new integration is required. Vendor profile extensions (location, contacts, about, intelligence report) are managed through the existing admin-portal surface and its admin-role-protected endpoints.
- **Auth (native email/password + Supabase Auth)**: No changes. The vendor detail view is publicly browseable; the existing auth modal behavior triggered by `HeaderBar` remains unchanged.
