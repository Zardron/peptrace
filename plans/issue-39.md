## Summary
Implement the new `/vendors` route and `VendorsList` screen per the Figma baseline addition (1,398 nodes). The screen is composed of the existing shared `HeaderBar` and `SiteFooter`, plus a new main content area with a title section, search/filter toolbar, and an 8-column data table. Because the issue touches data (100 vendor rows), the plan extends the backend `GET /vendors` endpoint and the `Vendor` database entity to support the full column set, while the frontend initially renders from a typed mock-data file to keep the component clean and API-replacement trivial. All five labeled layers are addressed: **frontend** (new screen and route), **api** (endpoint enrichment), **database** (schema extension), **iOS/Android** (no native changes required), and shared services (no changes required).

## API Changes
Extend the existing `GET /vendors` endpoint (listed in the app spec API surface) to return the enriched vendor list data required by the new screen. The current spec `Vendor` entity only exposes `name`, `pricePerMg`, and `rating`, which does not cover all table columns.
- **Route**: `GET /vendors`
- **Request shape**: Optional query parameters `?search=string&criteria=string` (infrastructure for future toolbar integration).
- **Response shape**: `{ vendors: Array<{ id: string, name: string, score: number, cost: string, tests: number, products: number, latest: string, location: string }> }`
- **Action**: EXTEND the response shape and underlying query. If the concrete endpoint is absent in the current codebase despite the spec, it should be created to match this contract.
- **Integration**: Frontend mock-data types in `vendorData.ts` must align with this schema so that replacing the static import with a live fetch is a trivial swap.

## Data Model Changes
Extend the `Vendor` entity in the app database to persist the fields surfaced in the API and UI.
- **Entity**: `Vendor` (app DB)
- **Fields to add**:
  - `location` (`text`) — new scalar attribute.
  - `tests_count` (`integer`, default `0`) — denormalized count of related `Test` records for fast list rendering.
  - `products_count` (`integer`, default `0`) — denormalized count of related products/leaderboard entries.
  - `latest_test_date` (`timestamp`, nullable) — denormalized latest date from related `Test` records.
- **Existing field mapping**: `rating` is serialized as `score`; `pricePerMg` is serialized as `cost`.
- **Action**: EXTEND the `vendors` table schema and provide a migration. Alternatively, a `vendor_stats` materialized view may be used if the team prefers computed fields, but denormalized columns are simpler for the list query.
