**Screen & route:** The three Figma frames (`4:33` iPhone, `4:31` iPad, `1:2` Desktop) form **one responsive screen group** for the `/` route. Do **not** split this into `MobileApp` and `DesktopApp` components. All responsive behavior is handled within a single component tree using CSS media queries at **567px** and **1092px**, inferred from the containing frame widths.

**Component strategy:** All sections and components are classified as **CREATE** because no mappings exist in `figma_code_mappings` and the codebase contains only starter markup. Shell sections—`Header`, `Footer`, `PromoBanner`, and `Newsletter`—are created as shared components under `frontend/src/components/` even though only the Leaderboards screen exists today, following the factory rule that a Figma page boundary is not a code component boundary.

**Sub-component decomposition:** The large `leaderboards` section is decomposed into semantically distinct children (`LeaderboardHeader`, `RankBy`, `PeptideTabs`, `LeaderboardCard`, `LeaderboardTable`, `LeaderboardCardLink`, `LeaderboardCardFooter`) rather than a single monolithic file. They are co-located in `frontend/src/components/leaderboards/`. No generic `Card` or `Tabs` primitive is introduced yet; premature abstraction is avoided until a second use case appears.

**Assets:** The brand `Logo` is an SVG asset (`frontend/src/assets/logo.svg`) that must be exported from Figma; its exact vector paths are not available in the structural diff.

**State:** Interactive state—active tab (`all peptides` vs `all vendors`), active peptide tab, `rankBy` toggle, and filter chips—is owned locally inside `Leaderboards` via React `useState`. The table rows render from a mapped array, not hard-coded JSX, to prepare for future API integration.
